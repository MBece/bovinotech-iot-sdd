**PASS.**

- Solo un usuario `VETERINARIO` puede resolver (`201`).
- El motivo es obligatorio (validación de navegador y `422` en la API).
- El ticket queda `CLOSED` y conserva la trazabilidad de la decisión.

- Los snapshots y las discrepancias se conservan.

## 6. Limitaciones

1. El E2E fue ejecutado por A0, no por A5, por una restricción de permisos del
   shell de A5. La evidencia cruda de A0 se conserva sin modificaciones.
2. El `403` del E2E se ejecutó contra el ticket `#2` (abierto según el log del
   backend) y el `409` contra el ticket `#1` (cerrado). Ambos demuestran el
   comportamiento exigido, pero no son el mismo ticket. Las pruebas de contrato
   y seguridad cubren `403` y `409` sobre el mismo ticket creado para cada
   prueba.
3. La validación del motivo vacío en el E2E es la del navegador
   (`Rellena este campo.`); la validación de servidor (`422`) se verifica en
   Pytest.
4. Las fechas visibles en la UI están en hora local; en la corrida final la API
   serializa los instantes UTC con sufijo `Z` (`comparedAt`, `closedAt`,
   `resolvedAt`).
